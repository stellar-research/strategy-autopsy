# strategy-autopsy

[English](README.md) | **日本語**

**トレード講座で教えられている手法をコードに落とし、15 年分の先物データでバックテストして、本当に儲かるのかを検証しました。**

これまでに検証した Al Brooks のプライスアクションと ICT / スマートマネーコンセプト（SMC）のルールは、**どれもコスト控除後に信頼できる優位性を示しませんでした。** このリポジトリでは、すべてのルール・コード・結果を公開し、あなた自身の手法を同じ方法で検証するための手順も提供します。

> ⚠️ ここに儲かる手法はありません。本リポジトリは研究・教育目的のみであり、投資助言ではありません。

---

## なぜ作ったか

ネット上の手法の多くは、スクリーンショットや「高勝率」で売られています。ルールを事前に固定し、長期データで検証し、失敗した結果まで公開する人はほとんどいません。

私たちの手順はシンプルです（詳しくは [docs/method.ja.md](docs/method.ja.md)）。

1. **データを見る前にルールを登録する。** ルール・パラメータ・合格基準はバックテスト前に確定し、その後は変更しない。
2. **各ルールは一度だけ検証する。** 同じデータでパラメータを調整し直さない。
3. **アウトオブサンプルを封印する。** 2025-09 以降の MES 1 年分は、どの実験でも一度も使っていない。
4. **ランダム基準と比較する。** 各トレードの損切りと利確の距離から「ランダムに入った場合の勝率」を計算し、実際の勝率がそれを有意に上回るかを見る。
5. **コストを正直に計上する。** 手数料とスリッページを含め、スリッページ感度も確認する。

## わかったこと

- **勝率とリスクリワードは別々に調整できるつまみではない。** 方向性の情報がないエントリーでは、勝率はおよそ `損切り ÷（損切り + 利確）` になる。どう調整しても期待値はゼロ付近で、コストを引くとマイナスになる。
- **重要なのは、エントリーシグナルに方向性の情報があるかどうかだけ。** つまり実際の勝率がランダム基準を有意に上回るかどうか。
- **インサンプルの好成績は、ほぼ運。** 03、05、06 は 2 年分の MES インサンプルでプラスだったが、未使用のデータではすべて失敗した。
- **スマートマネーの概念の多くは、プライスアクションの言い換え。** 重ねても新しい情報は増えず、シグナルが減るだけ。
- **「見ればわかる」ときだけ儲かり、ルールにすると儲からない手法は、本当の優位性ではない可能性が高い。** ただし、このリポジトリが示すのは「これらの機械的なバージョンに優位性はない」ということであり、「裁量トレードは必ず無効」ということではありません。

## 自分の手法を検証する

```bash
pip install -r requirements.txt

# 0. エンジンが正直か確認する：純粋なランダムウォークでは、どのルールも損をするはず
python tools/random_walk.py --days 2000 --out data/random_walk.csv
python brooks/backtest.py data/random_walk.csv --symbol MES --strategy ai --target 1R --out results/random_ai
python tools/report.py results/random_ai/trades.csv --symbol MES

# 1. registry/ に登録票を書き（テンプレート：registry/TEMPLATE.ja.md）、先にコミットする
# 2. 自分のデータで一度だけバックテストする
python brooks/backtest.py data/your_data.csv --symbol MES --strategy pullback --target 2R --out results/my_test

# 3. レポート：勝率とランダム基準、z 値、スリッページ感度、年別
python tools/report.py results/my_test/trades.csv --symbol MES --out results/my_test/REPORT.md
```

ICT モデルは `ict/research.py`（ほかに `research_choice.py`、`research_ep2.py`）で実行します。使い方は各ファイルの冒頭にあります。

データ形式は [data/README.md](data/README.md) を参照してください。相場データは含まれていません。

**私たち自身の正直さチェック**（ランダムウォーク 2,000 日、`--seed 11`）：

| 手法 | 回数 | 勝率 | ランダム基準 | PF |
|---|---|---|---|---|
| Brooks `ai` | 245 | 51.4% | 51.6% | 0.85 |
| Brooks `fade` | 284 | 36.3% | 38.5% | 0.79 |
| ICT デイトレモデル（400 日） | 607 | 28% | — | コスト後 −0.18R、ミラー取引より良くない |

勝率は基準どおりで、コスト後は損失になっています。エンジンが未来のデータを覗いていないことがわかります。

## 限界

- **ルールは Brooks と ICT の概念に対する一つの客観的な定義にすぎません。** 定義が違えば結果も変わり得ます。あなたの定義を同じ手順で登録して検証していただくのは歓迎です。
- **Brooks のエンジンは実験後に整理したバージョンです**（個別にオフにできるフィルターをいくつか追加）。デフォルト設定で再実行しても、登録票の数字と完全には一致しない可能性があります。
- ICT-04 は CME 先物ではなく、指数 CFD の 5 分足を使いました。どの実験でも指標発表や FOMC の日は除外していません。
- バックテストには裁量判断が含まれません。裁量トレードに優位性があるかは、別の方法で検証する必要があります。
