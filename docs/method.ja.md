# 検証方法

[English](method.md) | **日本語**

このプロジェクトの目的は、儲かる手法を見つけることではありません。もっと狭い問いに答えることです。**固定ルールとして書いた手法に、コスト控除後もランダムを超える優位性があるか？**

答えを信頼できるものにするため、すべての実験は次の 5 つのルールに従います。

## 1. 先に登録し、それからバックテストする

ルール・パラメータ・データ範囲・合格基準は、結果を一切見る前に `registry/` に書いてコミットします。コミット時刻がその証拠です。

検証後にルールは変更しません。変更する場合は新しい登録票を作り、別の実験として扱います。

## 2. 各ルールは一度だけ検証する

同じデータでパラメータを何度も調整すれば、いずれ見栄えのよい組み合わせが出てきますが、それはほとんど運です。そのため、各登録票は一度だけ実行します。

## 3. アウトオブサンプルを封印する

データの最後の期間（例：MES の最後の 1 年）は最初から触らず、最終検証のためだけに残します。新しい実験では、まだ使っていない銘柄や期間を優先します。

## 4. ランダム基準と比較する

方向性の情報がないエントリーでは、利確に先に届く確率はおよそ次のとおりです。

```
ランダムな勝率 ≈ 損切りまでの距離 ÷（損切りまでの距離 + 利確までの距離）
```

つまり：

| リスクリワード | ランダムな勝率 | 期待値（コスト前） |
|---|---|---|
| 1 : 1 | 約 50% | ほぼ 0 |
| 1 : 1.5 | 約 40% | ほぼ 0 |
| 1 : 2 | 約 33% | ほぼ 0 |

損切りや利確の位置を動かしても、勝率とリスクリワードが入れ替わるだけです。検証すべきなのは、**各トレードの実際の損切り・利確から計算したランダムな勝率を、実際の勝率が有意に上回るかどうか**です。有意性は二項検定の z 値で測ります。

エンジン自体も**正直さチェック**に合格する必要があります。純粋なランダムウォークでは、勝率はランダム基準をわずかに下回り（差はコスト分）、全体では損失になるはずです。ランダムなデータで儲かるなら、バックテストにバグがあります。

## 5. コストを正直に計上する

- 手数料は実際のブローカーの料金で計算します。
- スリッページはデフォルトで片道 1 ティック。さらに 1 ティック、2 ティック追加した場合の感度も確認します。
- 成行注文はシグナル足の終値ではなく、次の足の始値で約定させます。

## この方法でわからないこと

- わかるのは「このルールのこの客観的な定義」に優位性があるかどうかだけです。別の定義なら結果は変わり得ます。
- 裁量判断は検証できません。裁量トレードに優位性があるかは、ブラインドテストなど別の方法が必要です。
- 過去に優位性がなかったからといって将来もないとは限らず、過去に優位性があったからといって将来も続くとは限りません。
